# Project Cost Granularity Controller

Full-stack application generated by ApexStudio. You own all of it.

## Run everything

```bash
docker compose up --build
```

Frontend on http://localhost:5174, backend on http://localhost:8000.

## Structure

- `frontend/` — Vite + React + Tailwind UI.
- `backend/` — FastAPI: insights from PostgreSQL (`database/`); auth, RBAC, CRUD, file upload, SSE on SQLite.
- `database/` — PostgreSQL schema and workbook loader for the dashboard data.

## Run without Docker

Backend: `cd backend && DATABASE_URL=postgresql://localhost/cost_granularity ./run.sh`. Frontend: `cd frontend && VITE_API_URL=http://localhost:8000 npm run dev`.

## Input data and insights

The dashboard data lives in PostgreSQL: the `cost_granularity` schema built by
`database/schema.sql` and filled by `database/load_workbook.py` (see `database/README.md`).
The backend connects with `DATABASE_URL` (default `postgresql:///cost_granularity`, i.e.
libpq defaults); `APEX_PG_SCHEMA` and `APEX_FISCAL_YEAR` override the schema and the
fiscal year (default: the latest year with SAP actuals).

- `backend/apexapp/pgsource.py` reads the tables and formula views (`v_sap_wbs_ytd`,
  `v_purchase_order_summary`, `v_po_allocation`, `v_copperleaf_by_submission`) in one
  read-only snapshot.
- `backend/apexapp/insights.py` joins the three grains — PO Summary (commercial),
  SAP Data (posting), Actual Allocation + Copperleaf (analytical) — and derives KPIs,
  drill-downs, control totals and rule-based exceptions mapped to the requirement IDs
  in `Cost_Granularity_Guardrails_and_Must_Requirements_Share.docx`
  (catalogue in `backend/apexapp/requirements.py`).
- `GET /api/insights` returns everything; `/api/insights/{section}`,
  `/api/insights/pos/{po}` and `/api/insights/projects/{project}` return slices.
  Results are cached and recompute when a new load is recorded in `etl_load`
  (edits made directly in SQL without a reload are not picked up until restart).
  503 means the database is unreachable or empty; 422 means the schema is missing
  a table, view or column the engine reads.
- Without `VITE_API_URL` the frontend reads `frontend/src/lib/insightsSnapshot.json`.
  Regenerate it from the database:
  `cd backend && python3 -m apexapp.insights --export ../frontend/src/lib/insightsSnapshot.json`

`backend/apexapp/workbook.py` is no longer used by the backend; it stays as the column
contract that `flowise/build_flow.py` reads.

`frontend/legacy-pages/` holds the original generated pages that ran on mock data;
they are no longer routed and can be deleted.
