# Project Cost Granularity Controller — backend

Generated by ApexStudio. FastAPI. Dashboard insights are read from PostgreSQL
(`DATABASE_URL`, schema `cost_granularity` from `../database/`); users, files and
generic entities stay in SQLite.

## Run

```bash
./run.sh   # or: uvicorn apexapp.main:app --reload --port 8000
```

Point the frontend at it by setting `VITE_API_URL=http://localhost:8000`.

## What's inside

- `apexapp/schema.py` — the data model (tables generated from it).
- Auth (`/api/auth/register|login|me`), pbkdf2 hashing + signed tokens.
- Role-based access control (`apexapp/rbac.py`).
- CRUD for every entity at `/api/entities/{table}`.
- File upload/download at `/api/files`.
- Real-time SSE stream at `/api/events`.
- AI proxy at `/api/ai/chat` (uses ANTHROPIC_API_KEY; simulates if unset).
- AI Assistant proxy at `/api/ai/assistant`: forwards `{question, history}` to the Flowise flow at
  `FLOWISE_ASSISTANT_URL` (plus `FLOWISE_API_KEY` if set). It adds the logged-in user's email as `userId`
  for conversation history; see `../mcp-server/README.md`.
- Integration proxy at `/api/integrations/{name}` (secrets from env).
- Payments at `/api/payments/checkout` (Stripe; simulates if unset).

Default admin: `admin@demo.app` / `admin` (change or remove in `seed.py`).

## Postgres

`apexapp/pgsource.py` loads the insight engine's input from the `cost_granularity`
schema (tables plus the formula views) and `apexapp/insights.py` builds
`/api/insights` from it. Set `DATABASE_URL` (default `postgresql:///cost_granularity`).
The auth/CRUD layer (`apexapp/db.py`, `apexapp/crud.py`) is still SQLite.
